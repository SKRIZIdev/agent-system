# Нормы внутренней перелинковки

Единый свод для всех сайтов. Владелец — Интера (`intera`): она ведёт перелинковку и правит этот файл. `text-writer` ставит ссылки в текстах по §2–§4, `reviewer` проверяет по §2–§4 и §7.

Источники: гайд «полный цикл работы с внутренней перелинковкой» v2.0.0, прежние правила перелинковки из агентов текста и ревью, решения владельца от 2026-11-02.

## 0. Что главнее

1. **Решение владельца по проекту** — карточка проекта в волте (`<волт>/<раздел>/Проекты/`), `CLAUDE.md` и брифы в корне проекта, прямое указание в задаче. Пример: на одной из сеток сайтов по 5–6 бренд-ссылок на главную с каждой страницы (отдельный скрипт), а не одна.
2. **Постоянные нормы** — §2–§4 ниже.
3. **Операционные квоты сессии** — задаются в `targets.json` (минимум exact, квота на главную, список доноров).

Решение проекта сильнее нормы: выполняем его и один раз отмечаем в отчёте («по решению владельца, норма такая-то не применяется»). Норму в коде проекта под себя не переписываем.

## 1. Термины

- **Content-ссылка** — ссылка в теле основного текста: абзацы, списки, таблицы, подсказки внутри статьи. Не считаются: шапка, меню, подвал, хлебные крошки, оглавление, блоки «похожие статьи», карточки-плитки (ссылка с картинкой или заголовком внутри), кнопки, hero, заголовки `h1–h6`. Все нормы ниже — про content-ссылки, если не сказано иное.
- **Донор** — страница, с которой стоит ссылка. **Цель** — страница, на которую она ведёт.
- **Exact** — основной ключ цели дословно. Один exact на цель (можно с утверждёнными вариантами написания).
- **LSI / partial** — вариации ключа из реального спроса (GSC, карта ключей): с уточнением, другим порядком слов, синонимом.
- **Brand** — название сайта или бренда (утверждённые варианты перечислены в `targets.json`).
- **Descriptive** — описательная фраза о содержании цели без ключа.
- **Generic** — «здесь», «подробнее», «read more», «aquí», голый URL. Запрещены.
- **Типы страниц:** `home` (главная и главные языковых версий `/br/`, `/de/`…), `money` (зарабатывающая: топ, рейтинг, обзор с партнёрской ссылкой), `category`, `hub`, `info`, `policy` (privacy, terms, cookies, disclosure, responsible use…).
- **Индексируемая** — без `noindex`, canonical указывает на себя, отдаёт 200.

## 2. Где ссылка может стоять, а где нельзя

Внутренняя ссылка ставится **только из предложения основного текста страницы**: абзац статьи, пункт списка, который сам является фразой, ячейка таблицы с текстом, подсказка или врезка внутри статьи, ответ в FAQ.

Нельзя ставить и нельзя считать перелинковкой:

- заголовки `h1–h6` и вопросы FAQ (`<summary>`, заголовок вопроса);
- hero и первый экран: заголовок, подзаголовок/лид, плашки, бейджи, кнопки hero;
- шапка и меню (в том числе мобильное), подвал, хлебные крошки, оглавление;
- кнопки и CTA, липкие панели, сайдбар, виджеты;
- карточки и плитки (ссылка с картинкой или заголовком внутри), блоки «похожие статьи», «читайте также», «все гайды»;
- подписи к картинкам, alt, title, мета-теги, schema.

Единственное исключение — служебная пометка рядом с партнёрской кнопкой («affiliate link · how we earn» → страница disclosure). Это требование раскрытия, а не перелинковка. Его не трогаем и в квоты не считаем.

### Распределение по тексту

- **В одном предложении — не больше одной ссылки.**
- **В одном абзаце (пункте списка, ячейке) — не больше одной ссылки.** Ссылка на главную тоже считается.
- Ссылки разнесены по разделам: если ссылок 4 и больше, а разделов `h2` 3 и больше, ни в одном разделе не больше половины ссылок.
- Не все ссылки в последней четверти текста, и не «блок ссылок» в конце статьи вместо ссылок по тексту.
- Разбить предложение на два, чтобы развести ссылки, — не решение: в абзаце всё равно остаётся одна ссылка.

## 3. Исходящие: каждая внутренняя индексируемая страница

| Норма | Правило |
|---|---|
| Ссылка на главную | **Ровно одна** content-ссылка на главную своей языковой версии (если у проекта нет своего решения). Анкор: бренд, exact или LSI главной — по правилу длины ниже. |
| Плотность | Внутренние ссылки — по объёму текста: от `знаков ÷ 650` (минимум 1) до `знаков ÷ 400` (с округлением вверх), **потолок 10**. Нижняя граница не выше 6: длинный текст в норме при 6–10. 1000 знаков → 1–3, 2000 → 3–5, 4000 и больше → 6–10. Ссылка на главную в счёт не идёт. |
| Один URL — одна ссылка | На одну цель — одна content-ссылка со страницы. Self-ссылок нет. |
| Место | Только из предложений основного текста (§2): одна ссылка на предложение и на абзац, разнесены по разделам. |
| Анкор | Осмысленная фраза о содержании цели, на языке сайта. Не generic, не голый URL, без домена с TLD (домен — только в `href`). Без запрещённых слов проекта: список берётся из памяти или `CLAUDE.md` проекта (например, слова, запрещённые политикой площадки, и их переводы) и переносится в `forbidden` в `targets.json`. |
| Длина анкора | **1–2 слова** — сам ключ цели, а не фраза и не предложение. 3–4 слова — только если это дословно exact или LSI цели из анкор-листа и короче его не сказать (сократить — значит получить чужой ключ). **5 слов и больше — никогда.** Служебные слова вокруг ключа в ссылку не входят: «the [best laptops]», а не «[the best laptops]»; «в [гайде по размерам]» → «в гайде по [размерам ноутбуков]». Слово через дефис считается одним. |
| Куда нельзя | На `noindex`, 404, редирект, `/go/`-ссылки (партнёрские — не перелинковка). |
| Policy-страницы | Как доноры свободны от нормы плотности и ссылки на главную: это служебный текст. |
| HTML-карта сайта | `/sitemap/` и подобные не проверяются как доноры и не нужны как цели. |

## 4. Входящие: каждая цель

| Норма | Правило |
|---|---|
| Минимум входящих | **≥3** content-ссылки с разных доноров на каждую индексируемую страницу, кроме главных, policy и HTML-карты. На маленьком сайте — не больше, чем `страниц − 1`. |
| Сироты | Нет. Каждая индексируемая страница достижима с главной по ссылкам. |
| Глубина | Money и category — не дальше **2 кликов** от главной (считаются любые ссылки, включая меню). Остальные — не дальше 3. |
| Бренд | Бренд-анкор ведёт **только на главную** (на главную своей языковой версии). Фраза, где бренд стоит рядом с ключом («Acme Laptop sizes»), — это уже partial, не бренд. |
| Каннибализация | Один exact → **один URL** на всём сайте. Одинаковый описательный анкор на разные URL — тоже избегать. |
| Exact на money/category | **Минимум 3** (или все, если ссылок меньше 3). Пока ссылок меньше 50 — держим ровно 3, остальное — LSI и описательные. От 50 ссылок — потолок **10%**. Формула: от `min(3, всего)` до `max(3, 10% от всего)`. *Решение владельца 2026-11-12 (было 5): при малом числе входящих 5 exact давали 70–80% точных вхождений — переоптимизация.* Уже живые на проде ссылки ради нормы не перетряхиваем — применяем к новым страницам и при следующих правках. |
| Exact на остальные цели | Минимума нет, потолок тот же: `max(5, 10% от всего)`. |
| Exact на главную | Операционная квота, по умолчанию около трети: пример из гайда — ≥10 exact из ≥28 ссылок. Остальное — бренд и LSI. Задаётся в `targets.json` (`home_quota`). Если ключ главной и есть бренд (бренд-сайты, где имя бренда и есть главный запрос), бренд-анкор на главную считается exact. |
| Распределение | 70–90% ссылок на цель — brand / LSI / descriptive. Exact — потолок, а не цель. |
| Повтор LSI | Один LSI или partial анкор — **не больше 20%** ссылок на цель (при 5+ ссылках). Меньше 5 ссылок — без повторов. |
| Пул LSI | 8–12 вариантов на цель из **реальных запросов**: GSC за 6 месяцев по этой странице. Нет GSC — карта ключей проекта, Ahrefs (ключи сайта, Keywords Explorer). Не выдумывать. Брать короткие формулировки (1–2 слова, максимум 3–4, если короче запрос не задают). Длинный хвост на 5 слов и больше анкором не бывает: из него берётся ядро. |
| Policy | Не больше **30** уникальных content-доноров на policy-страницу. Меню и подвал в этом счёте не участвуют и в прогоне не трогаются. |

Порядок, кого оставлять при сокращении ссылок на policy (KEEP): 1) legal, policy, methodology; 2) хабы и money; 3) ключевые справочные страницы темы; 4) главная и «о нас»; 5) до 3–5 сильных обзоров, где ссылка естественна.

## 5. Как править текст

- **Переписывать предложение**, а не подменять текст внутри `<a>`: анкор должен читаться естественно в своём предложении.
- Встраивать ссылку в **существующий** абзац по теме цели. Новые секции и абзацы ради ссылки не добавлять.

### Нужна ссылка, а подходящего анкора в тексте нет

Правильный анкор важнее удобного места. Неправильный анкор не ставим только потому, что такая фраза уже есть в тексте: generic, анкор не про цель, бренд не на главную, exact чужой страницы. Порядок действий:

1. **Фраза уже есть.** В абзаце по теме цели уже стоит нужный exact или LSI, и предложение читается естественно — оборачиваем ссылкой **только ключ** (1–2 слова, §3 «Длина анкора»), а не всё словосочетание вокруг него.
2. **Переписать предложение.** Предложение по теме есть, нужной фразы нет — переписываем это предложение так, чтобы анкор вошёл естественно. Смысл, факты и цифры те же, меняется формулировка.
3. **Переписать кусок абзаца.** Подходящего предложения нет, но абзац по теме цели есть — переписываем 1–2 предложения или добавляем в этот абзац одно связующее предложение с анкором («Под небольшую квартиру удобнее [торс-куклы]: они легче и занимают меньше места.»). Только факты, которые уже есть на странице или на странице-цели, без новых цифр и обещаний. Тон и язык — как у сайта. Абзац не вырастает больше чем на одно предложение.
4. **На странице нет абзаца по теме цели** — на этом доноре ссылку не ставим, берём другого донора из кандидатов. Если донор обязателен (например, для минимума входящих), ставим `BLOCKED_CONTEXT` с пометкой «нужен абзац → text-writer».

В журнале правок отмечаем, каким способом поставлена каждая ссылка: `wrap` (1), `rewrite` (2), `bridge` (3).

- Не трогать: другие цели, факты и цифры, дизайн, `h1–h4`, title и description, schema, меню, подвал, хлебные крошки.
- Шаблонное предложение, которое без ссылки теряет смысл, — **удалить целиком**, а не оставлять огрызок.
- Сохранять модель сайта (информационный, обзорный, коммерческий) и его голос. Без навязанных «купи», «жми», если сайт так не пишет.
- Формат ссылки — как принят на сайте: `<a href="/slug/">` (корневой путь, тот же слэш). Внутренним ссылкам не нужны `target="_blank"` и `nofollow`.
- Если сайт собирается из исходников (markdown, шаблоны, `build.py` / `gen.py`), правятся **исходники**, потом сборка. HTML после сборки должен совпадать с исходником, правка только в `dist` пропадёт при следующей сборке.

## 6. Статусы в постраничных пакетах

| Статус | Значит |
|---|---|
| `KEEP` | Ссылка в норме, не трогать. |
| `REWRITE_CONTEXT` | Переписать предложение: exact сверх квоты → LSI, повтор LSI → другой LSI, длинный анкор → ключ в 1–2 слова, generic → ключ цели, бренд не на главную → ключ цели. |
| `BLOCKED_CONTEXT` | Контекст не позволяет поставить или переписать ссылку естественно. Ставит Интера вручную, с причиной. |
| `DUPLICATE` | Вторая ссылка на ту же цель с донора — удалить ссылку (текст оставить, если он осмысленный). |
| `ADD` | Новый донор: где поставить, с каким анкором и каким способом (`wrap` / `rewrite` / `bridge`, §5). |
| `CUT` | Policy сверх 30: убрать ссылку, шаблонное предложение — целиком. |

## 7. Аудит после прогона

| Проверка | Норма |
|---|---|
| Exact на money/category | по §4 |
| Главная | квота из `targets.json` |
| Повтор LSI | ≤20% |
| Policy | ≤30 доноров |
| Новые ссылки | только с утверждённых доноров (`approved_donors`) |
| Другие цели | не откачены и не задеты (diff с фокусом) |
| Контекст | смысл не потерян: выборочно перечитать переписанные и урезанные абзацы |
| Исходник = HTML | после сборки граф строится по собранному сайту |
| §2–§3 по донорам | только из текста, одна ссылка на предложение и абзац, ссылка на главную, плотность, без дублей и self; вне текста ничего не добавлено (diff) |

## 8. Перед прогоном

- Снимок «до» записан: дата, цифры по целям (`linkgraph.py scan` → папка снимка).
- Цели и их типы утверждены, у каждой есть exact и пул LSI с источником (GSC, карта ключей).
- Квоты прописаны явно: минимум exact, квота главной, ≤30 для policy.
- Пакеты на цели собраны по свежему снимку, а не по старому.
- Запреты понятны: что не трогать, где сайт собирается, куда не заливать.
